# Agent instructions

Briefing for coding agents (Claude Code, Cursor, Codex) working in this repo. Claude Code loads it through `CLAUDE.md`.

This is the **Prize Savings** Scaffold-HBAR template: a no-loss prize pool where deposits earn native Hedera staking
rewards, draws schedule themselves through the Hedera Schedule Service (HSS), winners come from the PRNG system
contract, and deposits are mirrored as frozen HTS tickets. Read `README.md` → "How it works" before changing logic.

Use the package manager the project was created with (`packageManager` in the root `package.json`). Examples use
`yarn`; with npm use `npm run <script>`.

## Commands

```bash
yarn next:dev                          # frontend on http://localhost:3000 (reads the live testnet pool)
yarn foundry:test                      # PrizeLedger unit, fuzz and invariant tests
yarn foundry:test:e2e                  # full round on a real network (local node by default, E2E_NETWORK=testnet)
yarn next:test                         # vitest for utils
yarn next:check-types && yarn lint && yarn next:build

yarn foundry:account:generate          # deployer keystore
yarn foundry:compile && yarn foundry:deploy --network testnet|local [--keystore name] [--node id]
```

HTS (`0x167`), PRNG (`0x169`) and HSS (`0x16b`) only exist on Hedera networks, so Anvil/Hardhat chains and Foundry
forks can't run PrizePool. The local target is a Hiero Local Node (`npx @hashgraph/hedera-local start -d`), which runs
the real system contracts. **Do not add mocks of system contracts**: keep pure logic in `PrizeLedger` (tested in
Foundry) and prove Hedera behaviour in `test/e2e`.

## Invariants you must preserve

Ledger rules are fuzzed in `PrizeLedger.invariant.t.sol` and the Hedera-facing ones are asserted in `test/e2e`. If you
change accounting, extend those tests rather than weakening them.

1. `address(this).balance >= totalPrincipal`: principal is never spent, lent, or used for fees.
2. Σ `accounts[user].balance == totalPrincipal`, and `participants` is exactly the set of accounts with a balance.
3. Ticket (PST) total supply `== totalPrincipal`, and every holder's tickets are frozen.
4. A saver can always `withdraw` their full balance in one call.
5. `draw()` must never revert because of HSS: scheduling failures emit `ScheduleFailed` and the permissionless
   fallback (`roundEnd + drawGrace`) keeps the pool live.
6. No owner powers over principal. Do not add admin withdrawals, upgradeability, or an admin key at deploy.

## Hedera rules that bite

- **Units:** inside contracts amounts are **tinybars (8 decimals)**; wallets send **weibars (18 decimals)** as
  `value`. In the frontend use `hbarToWeibars` for `value`, `hbarToTinybars` for uint256 args, `formatTinybars` for
  reads. Never use `parseEther` on a contract argument.
- **HTS calls return response codes**; always pass them through `_check` (SUCCESS = 22). A frozen holding cannot be
  transferred or wiped: unfreeze first, refreeze after.
- **Accounts must be associated** with the ticket before receiving it; `useTicketAssociation` decides whether the UI
  shows the `associate()` button.
- **Staking elections** can only be set at creation through HAPI. Keep deployments in `deployPrizePool.js`.
- **HSS:** check `hasScheduleCapacity` before `scheduleCall`; scheduled calls are paid from the contract's balance and
  charged ≥ 80% of the gas limit, so keep `drawGasLimit` tight and the participant scan bounded. HTS calls cost
  hundreds of thousands of gas each on a real network (a deposit uses ≈ 0.9M); measure with `yarn foundry:test:e2e`.
- **Mirror node:** `/contracts/{id}/results/logs` needs a timestamp range when filtering by topic; we fetch the latest
  page and decode with viem instead.

## Frontend conventions

- Hooks: `useScaffoldReadContract` / `useScaffoldWriteContract` (not the `...ContractRead/Write` names). The contract
  name is `PrizePool`.
- DaisyUI components (`btn`, `card`, `tabs`, `table`) over raw Tailwind where one exists; Hedera brand colours come
  from `styles/globals.css`.
- Every data block needs loading, empty and error states.
- Imports use the `~~` alias. Add `"use client"` to components that use hooks.

## Style

| Style | Use |
| --- | --- |
| `UpperCamelCase` | types, components, contracts |
| `lowerCamelCase` | variables, functions |
| `CONSTANT_CASE` | constants |
| `_leadingUnderscore` | internal/private Solidity functions and storage |

Prefer `type` over `interface` in TypeScript, custom errors over `require` strings in Solidity, and NatSpec that
explains the Hedera-specific *why*. Comments should add information.

## Extending the template

- **Multiple prize tiers:** split `prizeAmount` in `draw()` and pick several targets from one seed
  (`keccak256(seed, round, i)`); keep invariant 3 by issuing tickets per winner.
- **More savers:** replace the linear scan in `PrizeLedger.roundWeights` / `pickWinner` with a sortition sum tree and
  update README "Costs".
- **USD display:** read Chainlink's HBAR/USD feed on Hedera testnet (`0x59bC155EB6c6C415fE43255aF66EcF0523c92B4a`)
  via `externalContracts.ts`.
- After changing the contract, run `yarn foundry:test` and `yarn foundry:test:e2e`, redeploy with
  `yarn foundry:deploy`, and run the harness validators (`yarn harness:validate`).
